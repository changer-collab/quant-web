## Codebase Patterns
- factor-lab 的 FormulaFactor 用受限 AST 手动递归求值，strategy-runtime 的 factorEval 只延迟导入并调用它，不在 runtime 内实现公式逻辑
- strategy-runtime 的 CLI 命令必须延迟导入下游包；测试可用 importlib 加 __import__ guard 防止顶层导入 quantforge_factor/quantforge_data 等
- backtest-engine 的 Trade 类来自 strategy-runtime 包（quantforge_strategy.order），不在 backtest-engine 内定义
- 所有 runner（BacktestRunner、MultiSymbolRunner、MultiStrategyRunner）都用 calc_metrics + calc_trade_stats 构建 BacktestResult
- _to_camel() 函数自动把 snake_case 字段转 camelCase，新增字段无需手动处理映射
- Windows 环境下时间戳用秒级（10位）测试，毫秒级（13位）在 equity_stats 模块有专门处理
- SSE 事件 data 字段：API `/complete` 路由中 `event.data = result`，result = `{ backtestResult, analysis }`
- 前端 `mapBacktestResultToReport()` 接收 `{ backtestResult: PythonBacktestResult, analysis }` 格式
- Obsidian sync 通过 Python CLI `syncBacktest` 命令由 Worker 在回测完成后触发
- Worker 的 BacktestHandler 已在第 89-100 行包含 Obsidian 同步 try-catch
- eslint 全局配置在根 `eslint.config.mjs`，需要 Node.js 运行时变量（`setTimeout`/`setInterval`/`clearTimeout`/`AbortController` 等）必须显式添加 globals
- API 路由 `task.ts` 引用了 web 端的 `ReportRiskWarnings` 类型，但该类型只在 web 包定义；API 有自己独立的 types.ts
- worker 包有三个独立的 Agent executor，构成了 "wrapper → converter → bridge" 调用链
- strategy-runtime CLI 子进程 stdout 强制 UTF-8，测试用 `subprocess.run(..., text=True)` 时也要显式 `encoding="utf-8"`，否则 Windows 中文环境会按 GBK 解码失败
- strategy-runtime 的 `commands/__init__.py` 也必须保持函数内延迟导入，避免导入单个命令时加载 sibling 命令的下游包依赖
- AI 预测策略复用 `AIPredictor` 时至少需要 21 根 bar 才有非空特征；组合择时器要按 symbol 隔离历史窗口，避免多标的 rolling 特征混用
